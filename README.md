# ozon-seller-mcp

MCP-сервер для [Ozon Seller API](https://docs.ozon.ru/api/seller). Даёт Claude доступ к кабинету продавца: каталог, цены, остатки, акции и автостратегии, аналитика, финансы, отправления FBS, поставки FBO, возвраты, вопросы покупателей, сертификаты и штрихкоды — 68 инструментов.

Внутри лежит и самостоятельный Go-клиент Seller API (`ozon/`) — его можно использовать отдельно от MCP.

**Записывать данные сервер по умолчанию не может.** Режим только для чтения включён из коробки, доступ на изменение открывается переменной окружения. Это осознанное решение: сервер отдаёт языковой модели доступ к живому магазину, и включать запись должен человек в конфигурации, а не удачная формулировка в переписке.

## Два способа запуска

| | stdio | Streamable HTTP |
|---|---|---|
| Где живёт | на вашей машине, Claude запускает подпроцессом | на сервере |
| Устройства | только эта машина | все, включая телефон |
| Ключ Ozon | на каждой машине | в одном месте |
| Права | `OZON_ALLOW_WRITES` | выбираются при подключении устройства |
| Доступ | — | OAuth 2.1 со своим экраном согласия |

Сетевой режим — [`docs/REMOTE.md`](docs/REMOTE.md), подключение устройств — [`docs/OAUTH.md`](docs/OAUTH.md).

## Получите API Озон

Получить ваш api-ключ и id пользователя можно в личном кабинете OZON-Seller
``
https://seller.ozon.ru/app/settings/api-keys
``

## Установка

Нужен Go 1.25 или новее — этого требует официальный SDK протокола.

```bash
go install github.com/MainAlexStark/ozon-seller-mcp/cmd/ozon-seller-mcp@latest
```

Проверьте ключи до того, как прописывать сервер в Claude — отлаживать молчащий MCP внутри клиента неприятно:

```bash
OZON_CLIENT_ID=... OZON_API_KEY=... ozon-seller-mcp --check
```

> С сентября 2026 новые ключи выпускаются на 3 месяца. Если сервер внезапно перестал авторизовываться — скорее всего истёк ключ, а не сломался код.

## Подключение к Claude Code [STDIO]

```bash
claude mcp add ozon \
  -e OZON_CLIENT_ID=ваш-id \
  -e OZON_API_KEY=ваш-ключ \
  -- ozon-seller-mcp
```

## Подключение к Claude Desktop [STDIO]

`~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) или `%APPDATA%\Claude\claude_desktop_config.json` (Windows):

```json
{
  "mcpServers": {
    "ozon": {
      "command": "ozon-seller-mcp",
      "env": {
        "OZON_CLIENT_ID": "ваш-id",
        "OZON_API_KEY": "ваш-ключ"
      }
    }
  }
}
```

## Подключение к Claude Desktop [Streamable HTTP]

После того как вы развернули OZON-SELLER-MCP по инструкции из [`docs/REMOTE.md`](docs/REMOTE.md) на вашей удаленной машине, вы можете подключить новый коннектор в claude-desktop

1. Claude Desktop → Settings → Connectors → Add custom connector
2. URL: https://example.com/mcp
3. Поля OAuth Client ID и Client Secret оставьте пустыми — сервер поддерживает динамическую регистрацию, Claude зарегистрируется сам
4. Нажимаете Connect → откроется браузер с экраном согласия

На экране согласия вводите пароль владельца и выбираете права.

Проверить, что подключение записалось:

```bash
ozon-seller-mcp --grants
```

Адрес вводите точно как есть, без завершающего слэша: resource в метаданных сверяется посимвольно, и ``https://example.com/mcp/`` уже не совпадёт.

Перезапустите Claude. Спросите «покажи статус подключения к Ozon» — сервер ответит через `ozon_status`.

## Четыре заслона на пути опасных действий

**0. Права выбираются при подключении устройства.** На экране согласия вы решаете, что разрешить именно этому клиенту. Подключая телефон, снимаете галочку «Изменение» — и получаете доступ, которым магазин изменить невозможно: проверка стоит в обработке каждого запроса, а не в настройках процесса. Каждое подключение отзывается отдельно (`--grants`, `--revoke`), токен живёт час и обновляется сам.

**1. Чтение по умолчанию.** Инструменты, помеченные как изменяющие данные, в обычном режиме отказываются работать и объясняют, как включить запись. Пока `OZON_ALLOW_WRITES` не выставлен, максимум, что может случиться, — лишний запрос на чтение.

**2. Страховка от потерянного нуля.** Перед изменением цен сервер читает текущие и сравнивает. Смена 6900 → 690 проходит любую проверку формата и молча уничтожает маржу: Ozon такую цену примет без возражений. Поэтому изменение больше 30 % останавливается и требует `confirm_large_change: true`.

```
Изменение цены больше чем на 30% — запись остановлена.

Чаще всего это опечатка в порядке величины (690 вместо 6900),
и она уничтожает маржу молча: Ozon примет такую цену без возражений.

  pp-mw-1234               6900.00 → 690.00  (90%)

Если изменение верное, повторите вызов с confirm_large_change: true.
```

Если текущие цены прочитать не удалось, запись не блокируется — иначе временный сбой парализовал бы работу, — но в ответ добавляется предупреждение, что проверка не сработала.

Та же страховка стоит на добавлении товаров в акцию: акционная цена — это цена, и опечатка в ней стоит столько же, но выглядит безобиднее, потому что «в акции же должно быть дёшево». Там она вдобавок знает потолок, который называет сам Ozon, и цену выше потолка отклоняет сразу — без подтверждения, потому что обсуждать нечего: такой товар площадка не примет в любом случае.

**3. Ограничение размера ответа.** Ответ на несколько мегабайт не «просто длинный»: клиент режет результат инструмента по числу токенов, и такой ответ до модели не доезжает вовсе — она видит отказ, не понимает причины и повторяет вызов. Поэтому длинные ответы обрезаются здесь: JSON — по элементам массива, так что наружу выходит валидный документ с отметкой о том, сколько осталось за кадром, и подсказкой, как сузить выборку.

## Если Ozon отвечает таймаутом

Значит, запрос до него не дошёл — виноват маршрут, а не ключ и не код. Самый частый случай: машина работает через VPN, а Ozon из-под него недоступен.

Сервер различает эти ситуации сам: отказ Ozon (`HTTP 401/403/404`) и сбой соединения (`СЕТЬ timeout/dns/refused`) дают разные подсказки, потому что чинить надо разное. Если ни один метод не ответил и все сбои сетевые, `ozon_api_selftest` скажет об этом прямо, не заставляя разбирать методы по одному.

Три способа развести VPN и Ozon разобраны в [`docs/NETWORK.md`](docs/NETWORK.md). Коротко: сервер на VPS в России (лучше всего — заодно решает задачу «на всех устройствах»), split tunneling или `OZON_PROXY` для одного этого сервера.

## Про версии методов Ozon

Ozon отключает старые версии методов по расписанию, и это главный источник поломок у любого клиента. Учтено:

- все пути собраны в одном файле — [`ozon/paths.go`](ozon/paths.go) — с историей переездов в комментарии;
- `ozon_api_selftest` прогоняет по одному минимальному запросу к каждому read-методу и показывает, какие отвечают, а какие нет;
- на HTTP 404 сервер сам подсказывает, что версия, вероятно, отключена.

Актуальные на сентябрь 2026 переезды уже применены: `/v5/product/info/prices`, `/v4/product/info/stocks`, `/v3/product/list`, `/v4/product/info/attributes`, `/v3/product/info/list`, `/v2/product/pictures/info`. Отключённый `/v3/finance/transaction/list` заменён тремя методами `/v1/finance/accrual/*`, и они устроены иначе: периода у них нет вовсе — начисления отдаются за один день или по конкретным отправлениям.

В FBO переезды прошли неравномерно: список отправлений уехал на `/v3/posting/fbo/list` (старый отключён 31.08.2026), а получение одного отправления осталось на `/v2/posting/fbo/get`. Поставки — на `/v3/supply-order/*`, остатки на складах Ozon — на `/v2/analytics/stock_on_warehouses`. Все они проверяются `ozon_api_selftest`: если ваш кабинет отвечает по другим версиям, это видно с первого вызова.

## Устройство

Разделение, которое стоит понимать при доработке:

- **Чтение** идёт через `Client.Call` и возвращает сырой JSON. Ozon регулярно добавляет поля в ответы; жёсткие структуры на чтении означали бы терять новые данные и чинить клиент после каждого обновления.
- **Запись** типизирована строго и валидируется до отправки. Здесь цена ошибки — испорченные карточки в живом магазине.

Добавить новый read-метод — несколько строк в `internal/tools`:

```go
r.Add(Spec{
    Name:   "ozon_new_thing",
    Path:   ozon.PathNewThing,
    Desc:   "Что делает и когда пригодится.",
    Schema: schema(obj{"limit": num("Сколько записей")}),
})
```

Сам протокол держит [официальный Go SDK](https://github.com/modelcontextprotocol/go-sdk): рукопожатие, согласование версий, оба транспорта. Пакет `internal/mcp` — тонкий слой поверх него, и граница проведена намеренно: инструменты не знают ни про JSON-RPC, ни про типы SDK, поэтому следующая смена версии протокола останавливается в одном файле, а не расходится по тридцати инструментам.

## Разработка

```bash
go test ./...       # тесты, включая сквозные против подставного Ozon
go build ./...
make check          # vet + gofmt + тесты
```

Отдельно проверяется, что подключение без права записи не может писать, — это центральная гарантия сетевого режима. Поток OAuth целиком (обнаружение → регистрация → согласие → токен → отзыв) проверяется в `internal/oauth/flow_test.go` против настоящего HTTP-сервера.

Сквозные тесты поднимают подставной Seller API и прогоняют весь путь: вызов инструмента → защита → клиент → HTTP. Страховка от опечатки в цене проверяется именно так — с фиктивной текущей ценой 6900 и попыткой записать 690.

Инструменты в тестах вызываются через настоящий протокол — клиент из `internal/mcptest` проходит рукопожатие и делает `tools/call`. Дёргать обработчик напрямую было бы проще, но тогда из-под теста выпадает ровно тот слой, где обычно и живут ошибки: форма аргументов и форма ответа.
