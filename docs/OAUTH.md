# OAuth: подключение устройств

## Что изменилось и почему

Раньше доступ закрывался длинным секретом в адресе: `https://домен/mcp/<64 символа>`. Это работало везде, включая телефон, но имело три изъяна, которые нельзя было починить, не сменив схему.

**Секрет в адресе.** Спецификация MCP прямо запрещает передавать токен в строке запроса: адреса оседают в журналах прокси, в истории браузера, в конфигурации клиента. Мы гасили это выключенным логированием путей в Caddy — но это защита от одного источника утечки из нескольких.

**Отзыв только скопом.** Убрать доступ у одного устройства было нельзя: смена токена отключала сразу все.

**Вечный срок.** Утёкший однажды секрет оставался годным, пока вы о нём не вспомните.

OAuth снимает все три. Токен живёт час и обновляется сам; каждое подключение отзывается отдельно; согласие даётся на конкретный набор прав.

Плюс появилось то, чего в прежней схеме не было в принципе: **вы решаете при подключении, что разрешить именно этому устройству**. Подключая телефон, снимаете галочку «Изменение» — и получаете доступ, которым магазин изменить невозможно, даже если очень попросить.

## Как это выглядит

```
Claude                     ваш сервер
  │                            │
  ├─ запрос без токена ───────►│
  │◄──── 401 + где метаданные ─┤
  │                            │
  ├─ читает метаданные ───────►│
  ├─ регистрируется (DCR) ────►│
  │                            │
  ├─ открывает браузер ───────►│  ← вы вводите пароль
  │                            │    и выбираете права
  │◄──── код авторизации ──────┤
  ├─ меняет код на токен ─────►│
  │◄──── токен на 1 час ───────┤
  │                            │
  ├─ работа с токеном ────────►│
```

Пароль вводите только вы и только в этот момент. Claude его не видит: он получает код, а код без вашего подтверждения не выдаётся.

## Настройка

### 1. Пароль владельца

```bash
ozon-seller-mcp --hash-password
```

Пароль читается со stdin, а не из аргумента: аргументы видны через `ps` и остаются в истории оболочки. Сам пароль нигде не хранится — на сервере лежит только PBKDF2-хеш.

Полученную строку положите в `OZON_OWNER_PASSWORD_HASH`.

### 2. Переменные окружения

```bash
# Внешний адрес сервера — он же включает OAuth.
OZON_PUBLIC_URL=https://ozon-mcp.example.com

# Хеш из предыдущего шага.
OZON_OWNER_PASSWORD_HASH=pbkdf2-sha256$600000$...

# Где хранить клиентов и токены. Файл переживает перезапуск —
# иначе каждый рестарт отключал бы все устройства.
OZON_OAUTH_STORE=/var/lib/ozon-seller-mcp/oauth.json
```

Каталог хранилища должен принадлежать пользователю службы:

```bash
sudo mkdir -p /var/lib/ozon-seller-mcp
sudo chown ozonmcp:ozonmcp /var/lib/ozon-seller-mcp
sudo chmod 700 /var/lib/ozon-seller-mcp
```

### 3. Проверка

```bash
curl -s https://ozon-mcp.example.com/.well-known/oauth-protected-resource | jq
```

Поле `resource` должно **точно** совпадать с адресом, который вы будете вводить в Claude. Расхождение в одном слэше ломает подключение, а сообщение об ошибке будет невнятным.

## Подключение устройств

Везде одинаково — адрес без всяких секретов:

```
https://ozon-mcp.example.com/mcp
```

**claude.ai, Desktop, мобильное приложение:** Настройки → Connectors → Add custom connector, вставить адрес. Откроется браузер с экраном согласия.

**Claude Code:**

```bash
claude mcp add --transport http ozon https://ozon-mcp.example.com/mcp
```

Он поднимет приёмник на случайном порту и откроет браузер сам.

### На экране согласия

Вам показывают: какое приложение просит доступ, на какой адрес оно вернётся, и галочки прав.

- **Чтение** — каталог, цены, остатки, заказы, аналитика, финансы.
- **Изменение** — создание и правка карточек, цены, остатки.

Для телефона оставьте только чтение. Смотреть продажи в очереди удобно, а менять цены с телефона вы всё равно не станете — зато потерянный телефон не станет проблемой.

Если все адреса возврата ведут на ваш же компьютер (так работает Claude Code), появится предупреждение. Это не сбой: такой адрес может занять любая программа на той же машине, поэтому подтверждайте, только если вы действительно только что начали подключение сами.

## Управление доступом

Посмотреть, у кого сейчас есть доступ:

```bash
ozon-seller-mcp --grants
```

```
ВЫДАЧА        ПРИЛОЖЕНИЕ         ПРАВА                       ДЕЙСТВУЕТ ДО
a3f9c21e0b4d  Claude (телефон)   ozon:read offline_access    2026-09-07 14:22
7b1e440ac9f2  Claude Code        ozon:read ozon:write        2026-09-07 15:03
```

Отозвать одно подключение:

```bash
ozon-seller-mcp --revoke a3f9c21e
```

Устройство теряет доступ немедленно, остальные продолжают работать. Именно этого прежняя схема не умела.

## Что устроено именно так и почему

**Токены непрозрачные, а не подписанные JWT.** Подписанный токен нельзя отозвать до истечения срока, не заводя отдельный список отозванных. Возможность отозвать доступ — главная причина перехода на OAuth, поэтому токены хранятся на сервере.

**В файле лежат не токены, а их SHA-256.** Утечка файла хранилища не даёт доступа.

**Refresh ротируется.** При каждом обновлении старый refresh удаляется, а вся прежняя выдача уничтожается целиком. Перехваченный refresh становится бесполезен, как только настоящий клиент им воспользуется. Это требование OAuth 2.1 для публичных клиентов, а Claude регистрируется именно как публичный.

**Отзыв убивает выдачу целиком.** Отзывать по одному токену бессмысленно: оставшийся refresh тут же выпустит новый access, и доступ вернётся.

**Проверяется audience.** Токен, выпущенный для другого ресурса, не принимается, даже если он подлинный. Без этого один общий провайдер личности открывал бы все сервисы разом.

**У loopback игнорируется порт.** Claude Code слушает случайный порт, а объявляет адрес без него. Послабление узкое: касается только адресов на машине пользователя, путь при этом сверяется точно.

**Ошибка в самом redirect_uri не возвращается перенаправлением.** Иначе сервер превратился бы в инструмент открытого редиректа: злоумышленнику достаточно было бы подставить свой адрес.

## Статические токены

Никуда не делись, но роль у них теперь одна — автоматизация:

```bash
ozon-seller-mcp --gen-token
```

Скрипт или соседний сервис не может пройти экран согласия, и заводить ради него человека в цикле бессмысленно. Для людей и клиентов Claude способ по умолчанию — OAuth.

При старте с включёнными статическими токенами сервер пишет предупреждение: они не истекают и не отзываются поштучно.

**Токена в адресе больше нет.** Прежние ссылки вида `/mcp/<секрет>` возвращают 401. Если что-то подключено по старой схеме — переподключите через OAuth.

## Ротация пароля

```bash
ozon-seller-mcp --hash-password         # новый хеш
sudo nano /etc/ozon-seller-mcp.env      # заменить
sudo systemctl restart ozon-seller-mcp
```

Уже выданные токены при этом продолжают работать: пароль нужен только для новых подключений. Если хотите отключить всё — отзовите выдачи через `--grants` и `--revoke` либо удалите файл хранилища.

## Если не подключается

**Claude не видит сервер.** Проверьте, что `401` возвращается с заголовком `WWW-Authenticate` и в нём есть `resource_metadata`. Без этого Claude не узнает, что сервер поддерживает OAuth:

```bash
curl -si -X POST https://ozon-mcp.example.com/mcp -d '{}' | grep -i www-authenticate
```

**Ошибка на этапе регистрации.** `/oauth/register` принимает JSON, `/oauth/token` — форму. Если между ними стоит прокси, переписывающий Content-Type, ломается один из двух.

**Метаданные не сходятся.** Поле `resource` обязано совпадать с введённым адресом посимвольно.

**Не доходит до сервера авторизации.** Запросы идут с адресов Anthropic (`160.79.104.0/21`). Если перед сервером стоит фильтр, он должен пропускать их и к `/mcp`, и к `/.well-known/*`, и к `/oauth/*`.

**Ответы медленные.** Claude ждёт 10 секунд на обнаружение, регистрацию и выдачу токена; 30 — на обновление. Медленный ответ выглядит как случайные обрывы подключения.
