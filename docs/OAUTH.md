# Вход, магазины и подключения Claude

## Кто есть кто

- **Пользователь** — учётная запись сервиса: почта и пароль. Регистрируется сам на главной странице.
- **Магазин** — пара Client-Id + API-ключ из кабинета продавца Ozon. У пользователя их может быть несколько. Ключ проверяется на живом Ozon до сохранения и хранится зашифрованным.
- **Подключение** (OAuth-выдача) — доступ одного приложения (Claude на ноутбуке, Claude на телефоне) к **одному** магазину с выбранными правами. Отзывается в кабинете поштучно.
- **API-токен** — то же самое для скрипта, который не может пройти экран согласия.

Почему подключение привязано к одному магазину, а не «ко всем магазинам пользователя с выбором в чате»: магазин, перепутанный моделью в аргументе инструмента, — это чужие товары по чужой цене. Выбор делает человек на экране согласия, дальше он зашит в токен, и ни один инструмент не принимает магазин параметром.

## Как это выглядит

```
Claude                     сервис                          браузер пользователя
  │                          │                                    │
  ├─ запрос без токена ─────►│                                    │
  │◄──── 401 + метаданные ───┤                                    │
  ├─ регистрируется (DCR) ──►│                                    │
  ├─ открывает браузер ──────┼───────────────────────────────────►│
  │                          │◄── не вошёл? → /login → обратно ───┤
  │                          │◄── нет магазина? → подключить ─────┤
  │                          │◄── выбрал магазин и права ─────────┤
  │◄──── код авторизации ────┤                                    │
  ├─ меняет код на токен ───►│   токен = пользователь + магазин + права
  │◄──── токен на 1 час ─────┤                                    │
  ├─ работа с токеном ──────►│ → ключ этого магазина → Ozon
```

Весь запрос авторизации переживает круг через вход и подключение магазина: после них пользователь возвращается на тот же экран согласия. Claude пароля не видит — он получает код, а код без подтверждения в браузере не выдаётся.

## Экран согласия

- **Учётная запись** — под кем выполнен вход. Подтвердить форму может только тот, кто её открыл: номер сессии согласия сверяется с cookie кабинета.
- **Магазин** — только магазины этого пользователя; номер из формы сверяется с его списком.
- **Чтение** — включено. **Изменение** — выключено, даже если приложение его просит: запись выдаётся явно. Подключая телефон, её обычно не включают.

## Что устроено именно так и почему

**Токены непрозрачные, а не JWT.** Подписанный токен нельзя отозвать до истечения срока. Токены хранятся на сервере, в базе — только их SHA-256.

**Удаление магазина убивает его подключения сразу.** Токены ссылаются на магазин с `ON DELETE CASCADE`: ни одного запроса к удалённому магазину после нажатия кнопки. То же при удалении учётной записи; блокировка администратором (`--disable`) отключает всё немедленно, не удаляя данных.

**Refresh ротируется, отзыв убивает выдачу целиком.** Перехваченный refresh бесполезен, как только настоящий клиент им воспользуется; оставшийся refresh не может воскресить отозванный access. Магазин и права переживают обновление токена.

**Проверяется audience.** Токен, выпущенный для другого ресурса, не принимается.

**Ключи магазинов зашифрованы с привязкой.** AES-256-GCM, мастер-ключ в окружении процесса. Шифротекст привязан к пользователю и Client-Id: переставленный в чужую строку базы, он не расшифруется.

**Кабинет без JavaScript.** Серверный HTML, строгий Content-Security-Policy, запрет встраивания во фреймы (иначе кнопку «Разрешить» можно было бы подсунуть под чужой клик), CSRF-токен на каждой форме, cookie `HttpOnly; Secure; SameSite=Lax`. Lax, а не Strict: подключение начинается переходом с claude.ai, и со Strict браузер не прислал бы cookie только что вошедшему пользователю.

**Вход не выдаёт, кто зарегистрирован.** Одна фраза на «нет такого адреса» и «не тот пароль», и PBKDF2 считается в обоих случаях — по времени ответа тоже не отличить. Вход, регистрация, смена пароля и удаление учётной записи ограничены по частоте с одного адреса: PBKDF2 намеренно дорог, и без ограничения форма входа — готовый способ загрузить процессор.

**Ошибка в самом redirect_uri не возвращается перенаправлением,** а `next` после входа принимается только внутри сайта — иначе сервер стал бы инструментом открытого редиректа.

**Регистрация клиентов открыта** (так требует MCP: Claude регистрируется сам). Клиенты, за сутки не получившие ни одного токена, удаляются фоновой чисткой.

## Если не подключается

**Claude не видит сервер.** `401` должен приходить с `WWW-Authenticate`, в котором есть `resource_metadata`:

```bash
curl -si -X POST https://ozon-mcp.example.com/mcp -d '{}' | grep -i www-authenticate
```

**После входа снова форма входа.** Cookie не доходит: сервис открыт не по `OZON_PUBLIC_URL` (другой домен или http вместо https).

**«Магазин этого подключения удалён или недоступен».** Магазин удалили в кабинете — подключите сервер в Claude заново и выберите другой.

**Ошибка на этапе регистрации.** `/oauth/register` принимает JSON, `/oauth/token` — форму. Прокси, переписывающий Content-Type, ломает один из двух.

**Метаданные не сходятся.** Поле `resource` обязано совпадать с введённым адресом посимвольно.

**Фильтр по адресам.** Запросы Claude идут с адресов Anthropic (`160.79.104.0/21`); фильтр должен пропускать их к `/mcp`, `/.well-known/*` и `/oauth/*`, а браузеры пользователей — ко всему остальному.

**Ответы медленные.** Claude ждёт 10 секунд на обнаружение, регистрацию и выдачу токена; 30 — на обновление.
