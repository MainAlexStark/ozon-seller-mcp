# Инструменты

54 инструмента. Помеченные **ЗАПИСЬ** изменяют данные в магазине и работают только при `OZON_ALLOW_WRITES=true`.

## Диагностика

Начинайте отсюда, когда что-то не работает.

| Инструмент | Что делает |
|---|---|
| `ozon_status` | Режим сервера, пороги защиты, кабинет продавца. Отвечает на вопрос «почему он отказывается менять цену» |
| `ozon_api_selftest` | По одному минимальному запросу к каждому read-методу. Показывает, какие живы, а какие Ozon отключил |

## Категории

Без `description_category_id` и `type_id` товар не создать — начинать всегда отсюда.

| Инструмент | Что делает |
|---|---|
| `ozon_category_tree` | Дерево категорий и типов товара |
| `ozon_category_attributes` | Характеристики категории: какие обязательны, какие словарные |
| `ozon_category_attribute_values` | Допустимые значения словарной характеристики |

Когда импорт падает с ошибкой валидации — почти всегда это незаполненная обязательная характеристика. Смотрите `ozon_category_attributes` для нужной категории.

## Каталог

| Инструмент | Что делает |
|---|---|
| `ozon_product_list` | Список товаров с фильтрами по видимости и артикулам |
| `ozon_product_info` | Подробности: название, категория, статусы, изображения, штрихкоды |
| `ozon_product_attributes` | Заполненные характеристики товаров |
| `ozon_product_pictures` | Изображения карточек и статус загрузки |
| `ozon_content_rating` | Контент-рейтинг и что именно снижает балл |
| `ozon_warehouse_list` | Склады продавца; `warehouse_id` нужен для остатков |
| `ozon_product_import` | **ЗАПИСЬ** Создать или обновить карточки |
| `ozon_import_status` | Статус задачи импорта; с `wait=true` дожидается результата |
| `ozon_product_update_attributes` | **ЗАПИСЬ** Обновить характеристики |
| `ozon_pictures_import` | **ЗАПИСЬ** Загрузить изображения по URL |
| `ozon_product_visibility_set` | **ЗАПИСЬ** Показать или скрыть товары |

Импорт асинхронный. Ответ `ozon_product_import` означает «задача принята», а не «товар создан»: реальный результат приходит только из `ozon_import_status`. Поэтому у него есть `wait=true` — с ним вы сразу увидите ошибки валидации.

## Цены и остатки

| Инструмент | Что делает |
|---|---|
| `ozon_prices_info` | Цены вместе с комиссиями и тарифами логистики |
| `ozon_stocks_info` | Остатки: сколько на складах, сколько в резерве |
| `ozon_stocks_by_warehouse` | Остатки FBS в разрезе складов. Нужен список `sku` или `offer_id` |
| `ozon_prices_update` | **ЗАПИСЬ** Изменить цены; со страховкой от опечатки |
| `ozon_stocks_update` | **ЗАПИСЬ** Изменить остатки; `stock: 0` снимает с продажи |

`ozon_prices_info` — единственный способ узнать реальную выплату по товару. Считать маржу по одной цене витрины бессмысленно: комиссия и логистика съедают заметную часть.

У `ozon_prices_update` есть аргумент `confirm_large_change`. Он нужен, когда изменение цены выходит за порог (по умолчанию 30 %). Ставьте его только после того, как цену проверил человек — он существует ровно для того, чтобы такое изменение не проходило автоматически.

## Аналитика

| Инструмент | Что делает |
|---|---|
| `ozon_analytics_data` | Метрики продаж с группировкой по товару и дате |
| `ozon_analytics_stocks` | Остатки в реальном времени с оборачиваемостью |

Метрики `ozon_analytics_data`: `revenue`, `ordered_units`, `hits_view`, `hits_tocart`, `conv_tocart`, `returns`, `cancellations`, `position_category`. Группировки: `sku`, `day`, `week`, `month`, `category1`…`category4`.

`ozon_analytics_stocks` свежее, чем `ozon_stocks_info`, и показывает, на сколько дней хватит запаса.

## Финансы

| Инструмент | Что делает |
|---|---|
| `ozon_finance_summary` | Свод начислений за период: начислено, удержано, чистыми — по дням, категориям и видам |
| `ozon_finance_by_day` | Один день. По умолчанию свод, сырые начисления — по `detail: true`. Без даты — вчера |
| `ozon_finance_postings` | Начисления по конкретным отправлениям: экономика продажи. До 200 номеров за раз |
| `ozon_finance_accrual_types` | Справочник видов начислений — расшифровка `type_id` |

Эти методы пришли на смену отключённому `/v3/finance/transaction/list`, но устроены иначе, чем он. **Периода у самого API нет:** начисления отдаются по одному дню за запрос, а `ozon_finance_postings` ищет не по датам, а по номерам отправлений (их берут из `ozon_postings_list` или `ozon_fbo_postings_list`).

Период собирает `ozon_finance_summary`: сервер сам обходит дни, следует за курсором внутри дня и складывает суммы. Наружу выходит несколько десятков строк вместо мегабайта — на живом магазине один декабрьский день в сыром виде весит 78 КБ, а свод за него укладывается в килобайт. Это не украшение: клиент режет ответ инструмента по числу токенов, и сырая выгрузка за месяц до модели просто не доезжает.

Начисления Ozon отдаёт медленно — десять запросов в минуту, — поэтому длинный период за один вызов не собирается. Если время вышло, свод возвращает посчитанное и день, с которого продолжить; предел одного вызова — 92 дня. Суммы в своде это **движение денег**, а не валовые продажи: плюс — начислено вам, минус — удержано.

## Вопросы о товаре

Вопрос — не разновидность отзыва. Отзыв пишут после покупки, и он объясняет прошлое. Вопрос задают до покупки, и он держит решение о ней: пока «влезет ли на полку 30 см» висит без ответа, товар не покупает не один человек, а все, кто открыл карточку после него.

| Инструмент | Что делает |
|---|---|
| `ozon_questions_count` | Сводка по статусам: есть ли вообще что разбирать |
| `ozon_questions_list` | Вопросы покупателей. Статус `NEW` — ещё не отвеченные |
| `ozon_question_info` | Подробности вопроса: текст, товар, автор, число ответов |
| `ozon_question_answers` | Ответы на вопрос — в том числе от других продавцов того же товара |
| `ozon_question_answer_create` | **ЗАПИСЬ** Ответить. Ответ виден всем под именем магазина; 2–3000 символов |
| `ozon_question_change_status` | **ЗАПИСЬ** Пометить просмотренным или обработанным. Видно только вам |

Методы вопросов Ozon открывает **только продавцам с подпиской Premium Plus** — как и отзывы. Без неё они отвечают отказом прав, а не пустым списком; сервер объясняет это отдельно, чтобы отказ не выглядел как проблема с ключом. Проверить доступ разом: `ozon_api_selftest`.

Статусы `ALL` и `UNPROCESSED` описывают выборку, а не состояние: они есть у фильтра списка, но проставить их нельзя.

## Возвраты

| Инструмент | Что делает |
|---|---|
| `ozon_returns_list` | Возвраты FBS и FBO одним списком: что, почему, в каком статусе, где лежит |
| `ozon_returns_dropoff_points` | Пункты выдачи с вашими возвратами и их количество |

Финансовые инструменты показывают удержания, но не показывают, из-за чего они возникли. Возвраты и есть это «из-за чего»: пока причина не видна, «месяц вышел в минус» остаётся фактом без объяснения, а решение — править описание, менять упаковку или снимать товар — зависит именно от объяснения.

**Фильтры взаимоисключающие:** за один вызов работает ровно одно условие. Просьба «возвраты по этому артикулу за август» переводится в два условия совершенно естественно, и Ozon отвечает на это общей ошибкой валидации, из которой правило не следует никак, — сервер объясняет это в ответе и называет конфликтующие условия.

## Сертификаты и штрихкоды

Документальная сторона карточки: условия, без которых товар не продаётся, при том что с самой карточкой всё в порядке. Обе проверки срабатывают поздно — на приёмке склада или на модерации.

| Инструмент | Что делает |
|---|---|
| `ozon_certification_required` | Категории, где сертификат или декларация обязательны |
| `ozon_certificates_list` | Загруженные документы: номер, тип, статус, срок действия |
| `ozon_certificate_products` | Товары, привязанные к документу, и статус проверки каждого |
| `ozon_certificate_bind` | **ЗАПИСЬ** Привязать документ к товарам |
| `ozon_certificate_unbind` | **ЗАПИСЬ** Отвязать товары от документа |
| `ozon_barcode_generate` | **ЗАПИСЬ** Выпустить штрихкоды для товаров, у которых их нет |
| `ozon_barcode_bind` | **ЗАПИСЬ** Привязать штрихкоды, уже напечатанные на упаковке |

**Загрузки файла сертификата здесь нет.** Метод `/v1/product/certificate/create` принимает `multipart/form-data`, а клиент отправляет JSON; переписывать его ради операции, которая всё равно требует человека с документом на руках, смысла мало. Файл загружается в кабинете — всё вокруг него доступно отсюда.

Привязка не мгновенная: успешный ответ `ozon_certificate_bind` означает «принято», а не «товары проверены». Результат показывает `ozon_certificate_products`.

Штрихкоды: `generate` — когда кода нет вообще, `bind` — когда код есть на упаковке, но не указан в кабинете. Повторная генерация создаёт второй код на тот же товар. Оба метода принимают до 100 товаров за вызов, и у них собственный лимит частоты — 20 вызовов в минуту, единственный, который Ozon называет прямо.

## FBO: заказы и остатки на складах Ozon

Схема, где товар лежит на складе Ozon. Вопрос здесь другой, чем при FBS: не «что отгрузить сегодня», а «что и куда везти заранее».

| Инструмент | Что делает |
|---|---|
| `ozon_fbo_postings_list` | Заказы FBO за период. Без дат берётся последняя неделя; постраничность курсорная |
| `ozon_fbo_posting_get` | Подробности одного заказа FBO |
| `ozon_fbo_stocks` | Остатки в разрезе складов Ozon: свободно, в резерве, в пути |
| `ozon_fbo_clusters` | Кластеры Ozon и склады внутри них |

`ozon_fbo_stocks` отвечает на вопрос, на который сводный остаток ответить не может: ноль в одном кластере не виден, пока в другом лежит запас.

## FBO: поставки

| Инструмент | Что делает |
|---|---|
| `ozon_supply_orders_list` | Заявки на поставку: что вы везёте или собираетесь везти |
| `ozon_supply_order_get` | Подробности заявок: склад, таймслот, статус, состав |
| `ozon_supply_order_items` | Состав поставки по `bundle_id` из предыдущего метода |
| `ozon_supply_orders_counters` | Сводка заявок по статусам — заодно показывает сами названия статусов |
| `ozon_supply_timeslots` | Свободные таймслоты приёмки по заявке |

Все инструменты FBO только читают. Создание поставки — многошаговый сценарий с асинхронными статусами, и цена ошибки в нём измеряется не карточками, а машиной, приехавшей не в тот день; поэтому запись сюда пока не заведена.

Идентификаторы заявок выглядят как числа, а Ozon ждёт строки — сервер приводит тип сам, так что можно передавать и то и другое.

## Типовые сценарии

**«Что продавалось в августе»** — `ozon_analytics_data` с `date_from`/`date_to`, метриками `revenue` и `ordered_units`, группировкой по `sku`.

**«Сколько я реально заработал за декабрь»** — `ozon_finance_summary` с `date_from` и `date_to`. Разбирать конкретный день — `ozon_finance_by_day`, конкретный заказ — `ozon_finance_postings`. Цена витрины и выплата — разные числа.

**«Выручка за прошлый год»** — `ozon_analytics_data` на такой период отвечает `date_to must be greater than date_from`, хотя даты верные: так Ozon сообщает, что период вышел за окно хранения аналитики (примерно три месяца). Переставлять даты бесполезно — считайте по деньгам через `ozon_finance_summary`.

**«Какие карточки недозаполнены»** — `ozon_product_list` → `ozon_content_rating` по полученным SKU. Рейтинг прямо говорит, каких полей не хватает.

**«Что заканчивается»** — `ozon_analytics_stocks`: показывает оборачиваемость, а не только текущий остаток.

**«Подними цену на 10 % по этим артикулам»** — `ozon_prices_info` для текущих цен, затем `ozon_prices_update`. Страховка пропустит: 10 % ниже порога.

**«Создай карточку»** — `ozon_category_tree` → `ozon_category_attributes` для выбранной категории → `ozon_product_import` → `ozon_import_status` с `wait=true`.

**«Что везти на склады Ozon»** — `ozon_fbo_stocks` покажет, где заканчивается, `ozon_fbo_clusters` — куда это везти, `ozon_supply_orders_list` — что уже в пути, чтобы не отправить второй раз.

**«Что с моей поставкой»** — `ozon_supply_orders_counters` для общей картины, затем `ozon_supply_orders_list` с нужным статусом и `ozon_supply_order_get` по идентификатору. Состав — `ozon_supply_order_items` по `bundle_id`.

**«Почему за месяц столько удержаний»** — `ozon_finance_summary` покажет сумму и вид начисления, `ozon_returns_list` — какие товары вернули и по какой причине. Одно объясняет другое: сумма без причины не подсказывает, что менять.

**«На какие вопросы ещё не ответили»** — `ozon_questions_count` (есть ли что разбирать) → `ozon_questions_list` со статусом `NEW` → `ozon_question_answers`, чтобы не написать второй ответ поверх чужого → `ozon_question_answer_create`. После разбора — `ozon_question_change_status`, иначе те же вопросы вернутся в следующую выборку.

**«Товар не принимают на складе»** — `ozon_product_info` покажет, есть ли у карточки штрихкод. Если нет — `ozon_barcode_generate`; если код напечатан на упаковке производителя — `ozon_barcode_bind`, иначе в кабинете окажется два кода на один товар.

**«Нужен ли сертификат на этот товар»** — `ozon_certification_required` по категории, затем `ozon_certificates_list`: возможно, подходящий документ уже загружен и его достаточно привязать через `ozon_certificate_bind`.
